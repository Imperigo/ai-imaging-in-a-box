## Die Gegenprobe, die den Anlass gibt

Wir haben die naheliegende Reparatur («dann stempeln wir eben») **nachgestellt**: dieselbe
glasfreie Datei, unverändert bis auf einen vollständigen, gültigen Herkunftsvermerk mit
`merkmale: {materialien: …}`.

```
Dieselbe glasfreie Datei, vollstaendig gestempelt:
   urteil: traegt    bestanden(): True    maengel: []    offen: []
```

Aus einem ehrlichen `ungeprueft` wird ein falsches «bestanden». Das ist der Grund für
diesen Auftrag: ein Stempel ohne scharfes Merkmal ist schlechter als kein Stempel.

## Was auf unserer Seite schon steht

Die glb-Ausfuhr von KosmoOrbit schreibt ab 02.09.2026 einen Vermerk nach eurem Vertrag
(`kosmo.modellstand/v1`, wörtliche Kennung), mit:

```
"erzeuger": "KosmoOrbit exportGlb",
"merkmale": { "materialien": "2026-09-02", "transparenz": "2026-09-02" },
"traegt": { "ifc_klassen": {...}, "n_materialien": N, "n_primitive": P,
            "n_primitive_mit_material": P, "n_materialien_blend": B }
```

Zwei Zusagen dazu:

* **`ifc_klassen` zählt das EINGEFÜGTE, nicht das Gefundene.** Ein Bauteil, das an einer
  Budget- oder Geschossgrenze scheitert, steht nicht im Modell und wird nicht behauptet.
  Die Schreibweise ist die der Norm (`IfcDoor`, nicht `IFCDOOR`) — eine Drift-Wache im
  Testlauf hält das fest, damit euer wörtliches Nachschlagen nicht ins Leere greift.
* **Ohne Übernahme kein `quelle` und kein `ifc_klassen`.** Ein hier gezeichnetes Modell
  hat keine Quelldatei; eine zu nennen wäre gelogen. Euer Prüfer meldet dann wie bisher
  `offen`, und das ist richtig.

Bis eure Messvorschrift steht, meldet euer Prüfer `transparenz` als «geführt, aber ohne
Messvorschrift» und bleibt bei `ungeprueft`. Das ist die gewollte Richtung — ein Vermerk
soll in diesem Entwurf nie einen Fehlpass erzeugen können, sondern höchstens eine noch
offene Prüfung benennen.

## Was wir NICHT tun

Wir fassen euren Code nicht an. `MERKMAL_MESSUNG` ist eure Messvorschrift, und wie ihr
sie formuliert, entscheidet ihr — wir liefern nur das Feld, an dem sie messen kann.

## Auflagen

- Ein fehlendes `IfcWindow` in `ifc_klassen` darf **kein** Mangel sein. Es heisst «der
  Erzeuger zählt Fenster nicht mit», nicht «dieses Modell hat keine» — dieselbe
  Unterscheidung, die ihr bei `IfcDoor` schon sauber trefft.
- `IfcWindow: 0` ist eine Messung und darf nie rot werden: ein Rohbau ohne Fenster ist
  ein zulässiger Zwischenstand.
- Regel 3: keine Benutzerpfade, keine echten Projektdaten.
